CI Pipeline Investigation
1. Investigation Summary
The initial GitHub Actions CI pipeline failed during execution. The runner logs showed that the configured test command could not be executed. After reviewing the workflow configuration and test code, two reliability issues were identified.

2. Issue 1 — Incorrect Test Command
Symptom
The GitHub Actions runner failed during the "Run Test Suite" step.

The workflow attempted to execute:

npm run test-ci

Diagnosis
The test-ci script does not exist in package.json. Therefore, GitHub Actions cannot execute the requested command and the workflow fails before the test suite can run successfully.

Fix
The workflow should use the test script defined in package.json:

npm test

This executes the project's configured test suite.

3. Issue 2 — Flaky Timestamp Test
Symptom
The test for GET /api/status compared the response timestamp with a new timestamp generated immediately after receiving the response.

Diagnosis
The test contained:

const expectedTime = new Date().toISOString(); expect(res.body.timestamp).toBe(expectedTime);

The timestamp generated by the application and the timestamp generated by the test are not guaranteed to be identical to the millisecond. Execution and network latency can cause the values to differ.

This makes the test unreliable, particularly on CI runners where execution timing can vary.

Fix
The test should verify that the timestamp exists and represents a valid timestamp instead of comparing it with a newly generated millisecond value.

4. Proposed Improvements
The CI workflow will be refactored into two jobs:

lint — runs npm run lint
test — runs npm test
The test job will use needs: lint, ensuring that tests execute only after the lint job succeeds.

The workflow permissions will also be restricted from write-all to:

permissions: contents: read

This follows the principle of least privilege.
